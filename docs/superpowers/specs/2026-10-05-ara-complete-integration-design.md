# REAPER 多轨原 GUI、完整片段变换与 HiFiGAN 缓存设计

中文设计，2026-10-05。用户将目标明确扩展为四项：保留独立 App；同工程多轨共用一个
原 GUI、每轨独立输出；完整支持 clip 位置/拉伸/渐变；考虑 HiFiGAN 重渲染缓存。
用户已授权本会话自主推进、不逐步询问，后续仅在最终做一次集中 review。

## 最新范围裁定：只做线性拉伸

2026-10-05用户明确“不考虑非线性拉伸，只做线性拉伸”。本条覆盖下文旧非线性要求：
固定正向倍率、BPM/timebase引发的整段线性倍率变化属于本轮；stretch markers、坡度、
段内tempo warp不再作为实现/最终验收门。遇到不支持的变换须明确拒绝，不用总倍率近似。
线性拉伸的曲线迁移、保调音频、布局、保存冷恢复、多轨隔离和缓存失效仍全部必达。
倒放继续暂缓；独立App/多轨原GUI/普通与自动fade/HiFiGAN缓存/长源门不变。

## 权威与完成标准

本文覆盖旧二期设计中“stretch/fades 不支持”的最终边界；旧文档仍是历史探针证据，
不能继续按其较小范围关闭目标。新文档不把“一段 WORLD 修音成功”当作 HiFiGAN 或完整
插件通过。当前 Windows x64/REAPER7.81 是实际宿主验收平台，独立 App 的跨平台代码
路径保留。此前用户明确暂不做倒放仍保留；非线性由上方最新用户范围排除。

位置/拉伸/渐变的“支持”包括宿主变化被正确读取、原GUI显示、参数时间映射、真实播放/
导出、保存冷恢复、缓存失效与多实例隔离。显示长度/数字变化但音频/曲线错误不算完成。
普通 fades 与 ARA content-based fades 是不同契约，不能互相冒充。

## 选定架构

沿用 `ara-project-workspace-design.md` 的真实文档级唯一编辑 actor。任意 FX 打开原
DockRoot 即可看到/编辑同工程所有已接入轨道，可聚焦当前轨，不需要逐轨开窗口。
其它宿主 FX 窗口是同一工作区的同步视图，不能形成独立 history/参数权威。

与此分离的是音频角色：playback renderer 只替换其分配区域的输入；纯 editor renderer
按照锁定 ARAInterface.h 透传宿主输入，仅在有真实预听信号时添加该信号。REAPER普通
片段淡化/region gain 通常位于宿主每region输出链，不能被末尾编辑实例再次混音覆盖。
每轨回送独立，不把全工程总混音送给每条轨。GUI/重推理/文件缓存不进入process。

播放头权威不能是任何renderer最后一次写入的共享时间。先通过有界原子诊断核实真实
实时/预取/离线来源，收敛持久编辑渲染来源；保留真正seek/loop和停播定位。不能以取
最大时间掩盖回跳，或让某个瞬时playback实例停处理就把整个工程误报成暂停。

## 宿主片段数据与参数坐标

ARA持续作为音频源与文档生命周期权威。位置、源窗口、modification/playback时间映射
从真实模型取得，不读本地文件冒充源。完整变换读取需要区分：线性倍率、保调/重采样
语义、tempo/timebase导致的整段线性伸缩，以及普通/自动交叉渐变长度与形状。
REAPER stretch markers/段内tempo warp只作不支持识别，不实现其音频。

锁定 `ARAPlaybackRegionProperties` 有时间段/变换flags，没有普通fade长度或曲线形状；
其content-based fade flags只表达由插件自行计算智能过渡。若标准ARA无法表达宿主的
完整参数，使用经过源码/官方头文件核对的REAPER原生宿主扩展读取辅助元数据，不能
猜vtable、把opaque hostRef强转MediaItem、按名字/仅路径/仅位置猜对应clip，更不能
通过ReaScript/读取用户RPP拼一个伪ARA模型。缺少准确宿主绑定时明确不可用并报告。

原内核 `state/model.rs` 已有stretch_markers、takes/playback_rate、fade/auto_fade长度/
shape/dir和envelopes，优先复用而非另造近似曲线或使用普通重采样冒充保调拉伸。
宿主几何只读，应用于原GUI和worker渲染；对普通宿主fade，GUI可显示宿主形状，但
插件PCM不能再烘焙一次而导致宿主二次淡化。content-based fade若协商给插件负责，则
只应用一次并按协议提供头尾范围。支持每种变换前必须有音频与边界oracle。

编辑语义随region内音频保持：移动/裁切/拆分/改变时间映射后，已有参数按稳定区域
身份与局部/源时间重新投影到原GUI的项目时间，不能仅保留旧绝对帧数组而使编辑漂移。
保存版本需兼容已归档v2状态，旧身份不能靠新会话序号猜归属。宿主模型变化与本地
未应用编辑同时发生仍明确Conflict并保留曲线，不能为了“同步”静默丢最后一笔。

## HiFiGAN缓存与调度

已读代码事实：`mixdown.rs` 的整clip缓存复用由 `sources.is_none()` 门禁挡住ARA宿主PCM
路径；宿主 `apply_host_pitch_edit` 使用完整PCM/实际DSP输入指纹隔离内部处理器缓存。
原kernel已有分析/mel/整clip byte-budget LRU 与磁盘render_cache，需核对各层真实键与
结果形态后复用。不能只删sources门禁，让ara URI/同路径旧音频命中文件缓存。

分三层：授权源PCM与原分析；HiFiGAN/HNSEP等源相关中间结果；目标参数合成PCM。
重采样/宿主摆放和淡化的便宜组合层与神经重推理分开。同一内容、同一局部参数的
两个renderer通过single-flight共用结果，不因view/实例随机namespace不同重复推理。
同一合成结果用于播放与导出；44100/48000输出尽量由原模型采样率结果派生，不重复
运行相同神经网络。原独立App的缓存语义保持，ARA采用单独明确的内容权威命名空间。

缓存键至少包含完整内容摘要/版本、准确源窗口、声道模式、模型内容摘要/算法版本、
实际renderer与处理后端、有效局部F0/效果/静态参数、时间映射与输出采样率。组件地址、
轨名、URI或viewId不能单独决定音频缓存身份。只移动clip/只改普通宿主fade/宿主gain
不应重跑HiFiGAN；改pitch/tension/model/源内容必须使相关合成层失效，中间层按依赖复用。

任务合并/取消、最新generation与model/scope检查仍执行。过期或失败结果不发布、不
污染成功缓存，保存立即保存参数权威，不以等待神经推理完成为前提。全部重任务在
worker；GUI明确pending/失败；process仅消费就绪、不可变、内存可读PCM，不查磁盘LRU。

内存LRU按字节计费/去重Arc，磁盘缓存有配额、原子写入、版本校验、损坏拒绝与清理；
回收在非实时线程。已有512MiB先导预算不暗中放宽；模型/GPU/分析/中间输出的额外
占用需单独实测记录。30秒源是旧探针限制，不能拿它当完整插件的最终素材上限。
长音频必须走有界分块准备/缓存，或有证据的预算策略；不能通过不支持正常长人声
来降低验收难度，也不能把磁盘映射可能的缺页IO放进实时回调。

## 新完成门

1. 独立App真实导入、参数编辑、合成/播放/保存；原Tauri入口/文件工作方式正常。
2. 无独立App时，一个原GUI双轨分别编辑/对照、原撤销重做与自动应用；逐轨独奏输出
   不串，全部FX关闭继续供音，保存冷重开未开GUI也恢复，多个工程不能互见。
3. 宿主移动/裁切/拆分/源变更以及线性拉伸（含tempo/timebase整段倍率变化）/普通手动
   fade/自动交叉fade的GUI、参数与最终音频一致；重新打开持久结果一致。
4. HiFiGAN实际模型与参数链有实测，记录冷/暖耗时、推理次数/命中、PCM与内存/GPU
   峰值；位置/fade-only不重复神经推理，真正参数/源/model变化正确失效。关GUI与冷
   重开复用正确，不能由一次WORLD输出外推HiFiGAN缓存通过。
5. 44100/48000、mono/stereo、短素材/30秒/正常长人声、多轨、连续快速编辑、seek/
   loop、播放头平稳与停播、冲突/取消/缓存损坏资源回归；最终一次集中review。

当前这些门尚未全部实现/验证；本文是新范围的设计，不是成功报告。
