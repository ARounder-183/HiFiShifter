# 音源制备与标记校准：独立制备、HiFiShifter 内校准

> 状态：按最新需求重写，未实施
>
> 日期：2026-11-10
>
> 消费方：[Ctrl+F 连续音选样：句段截取、元音优先与渐变导入](./2026-11-10-voicebank-quick-search-design.md)

## 1. 项目划分

音源制备使用独立项目，不把模型推理塞进 HiFiShifter，也不要求随 App 分发。
**校准 UI 本期合并进 HiFiShifter，但作为独立“音源校准”工作区，不嵌入时间轴
或 Clip 编辑体系。**

```text
独立音源制备项目
└── 整首纯人声 -> 自然断句 -> 每句 WAV + 配套标记

HiFiShifter
├── 音源校准工作区：文件总览 + 波形标记 + 播放头 + 区间试听 + tag
└── Ctrl+F：读取同一音源库 -> 搜索与截取 -> 普通 Clip
```

制备部分以较高效率的批处理自动化为目标，不做复杂服务、账户、任务系统或插件体系。
校准部分复用 HiFiShifter 的波形、解码、播放与快捷键基础设施，避免为了播放头、
可拖动标记和区间试听重新开发一套桌面 UI。音源制备与校准通过文件协议解耦。

本期不做歌词音符占位或选样任务层。

## 2. 音源制备：一首歌变成一组带标记的句子

### 2.1 输入与输出

输入：

- 一首歌的**纯人声音频**；
- 对应歌词、拼音或音素序列；
- 语言、词典及必要的特殊发音说明。

输出：

```text
voicebank/song-a/
├── 001.wav
├── 001.marks.json
├── 002.wav
├── 002.marks.json
└── ...
```

每个 WAV 是一个按自然间隔得到的完整句段。`ka`、`at` 等只是该句内部的标记范围，
不在制备阶段拆成大量单音文件。

### 2.2 处理流程

```text
整首纯人声 + 歌词
    ↓
检测自然停顿，得到候选句子范围
    ↓
人工确认句段边界与每句歌词
    ↓
按句导出 WAV，保留必要的句首/句尾余量
    ↓
逐句强制对齐，生成音节/音素/元音锚点草稿
    ↓
进入图形校准界面，调整范围、确认或禁用、添加 tag
    ↓
发布为 Ctrl+F 可读取的音源库
```

断句优先使用自然间隔，不要求每句严格对齐固定小节。不要在连续演唱中间仅因短空隙
或能量下降就强制断句；容易误分的位置留在校准界面合并或重划。

### 2.3 每句需要标记什么

| 内容 | 例子与用途 |
|---|---|
| 音节范围 | `ka / ta / na`，供单音与连续范围搜索 |
| 音素范围 | `k / a / t / a / n / a`，供 CV/VC 截取 |
| onset / nucleus / coda | 区分元音主体、起音和韵尾 |
| 元音起点与稳定区 | 元音优先检索、光标对齐和渐变交接 |
| 左右音节关系 | 从 `ka ta` 中识别跨音 `at` |
| 音高、时长等分析 | 候选排序与选择参考 |
| 校对状态 | 自动草稿、人工确认、需复核、禁用 |
| 自定义 tag | 用户分类、显示、筛选和搜索 |

例如：

```text
句子：ka ta
音素：k   a   t   a

可搜索：ka、ta、at、kata、整句
at 的来源：前音节 ka 的 a -> 后音节 ta 的 onset t
```

`at` 是跨音衔接，不是预先生成的独立 WAV，也不默认表示音节内 coda。

## 3. 校准工具：面向音频打标，而不是数值表

### 3.1 核心体验

> **用户能浏览所有文件，能在波形上看到所有标记的位置，能直接拖动调整范围，能立即听到调整后的结果。**

数值输入只能作为精确辅助，不能是主要编辑方式。主要交互参考音频标注工具：
文件列表、可缩放波形、区间选择、可拖拽边界、区间循环、标签编辑和审核状态。

### 3.2 为什么并入 HiFiShifter，但不复用 Clip 语义

校准需要的能力大多已有基础：源音频解码、波形 mipmap、播放与区间预览、播放头、
时间缩放/滚动、快捷键作用域、设置保存，以及主题与面板布局。独立新起一个 UI 会
重复建设这些设施，投入主要落在通用音频界面而不是校准本身。

但音素标记**不是 Clip，也不是 Take**。若直接复用时间轴 Clip，会把大量无关规则
带进校准：

- Clip 的移动、裁切、拉伸和淡化；
- 音高分析、参数曲线与合成渲染；
- Clip 级缓存失效与工程脏状态；
- 自动交叉淡化、轨道选择与工程撤销语义。

因此采用“复用底层能力、新建轻量标记面”的方式：

```text
PhraseAnnotationSurface
├── WaveformView       复用波形数据与绘制能力
├── PlayheadOverlay    点击/拖动定位、播放跟随、区间循环
├── SegmentLayer       音节与音素区间、角色和标签
├── BoundaryHandle     可拖动边界与共享边界更新
└── SelectionLayer     当前标记、截取范围与循环区间
```

播放头只需支持点击定位、拖动定位、播放跟随和循环区间，不引入完整时间轴传输系统。
标记编辑只更新音源标记模型，不调用 Clip 编辑命令。

```text
Phrase
├── segments[]：音节/音素区间
├── anchors[]：元音起点、稳定区等
├── tags[]：用户标签及作用范围
└── reviewState：校对状态
```

校准的撤销/重做和未保存提示只覆盖音源标记，不写入工程历史，也不使用户当前音频
工程变脏。保存标记只刷新相关音源索引，不触发 Clip 重渲染。

### 3.3 总体界面

```text
┌─────────────────────────────────────────────────────────────────────────┐
│ 音源库 singer-a     [全部文件] [待校对] [已修改] [已确认]   搜索/tag     │
├───────────────────┬─────────────────────────────────────────────────────┤
│ 文件              │ song-a / 003.wav                     [保存并下一句] │
│ 搜索文件名/tag     │ ka          ta          na          [编辑歌词]    │
│                   │                                                     │
│ 001.wav  已确认    │ 波形                                               │
│ 002.wav  待校对 3  │ ~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~~ │
│ 003.wav  编辑中    │ ├─ka─┤  ├─at─┤ ├─ta─┤  ├─an─┤  ├─na─┤            │
│ 004.wav  已确认    │ k│  a   │t│  a   │n│  a                          │
│ ...               │      ▲           ▲                                │
│                   │   可拖动边界    当前选中 at                        │
│                   │                                                     │
│ 003.wav 的全部标记 │ [整句] [ka] [at] [ta] [an] [na]                   │
│ ka at ta an na    │ [播放句] [播放范围] [循环边界] [播放左右组合]       │
│                   │                                                     │

```

### 3.4 文件总览

左侧文件列表不是简单的系统目录树，而是音源制备进度与质量入口：

- 显示所有句子文件、歌词摘要和时长；
- 显示待校对问题数、已确认/已修改/已禁用状态；
- 按文件名、歌词、音素或 tag 搜索；
- 支持只看问题项、最近修改或指定录音批次；
- 保存后自动来到下一待校对文件，也允许自由跳转。

### 3.5 波形与范围编辑

主区域提供：

- 鼠标滚轮/缩放控件改变时间尺度，拖动查看整句；
- 点击音素或音节区间选中，直接拖动左右边界；
- 拖动区间移动范围，或使用明确操作拆分、合并、新增和删除标记；
- 显示模型原始边界、自动建议和当前人工边界，可恢复自动结果；
- 同时查看完整句子与局部放大，避免只在数值框里调毫秒；
- 选中 `at` 时显示其左右音节和覆盖的音素，而不只是孤立一个区间。

修改共享音素边界时，两侧标记同步更新，避免无意留下空隙或覆盖。用于实际截取的
范围与元音对齐锚点可在波形上独立微调，不要求用户理解内部字段。

### 3.6 试听是校准主操作

| 试听方式 | 用途 |
|---|---|
| 播放整句 | 核对歌词、自然停顿与上下文 |
| 播放所选范围 | 听当前 `ka` 或 `at` 截出来是什么 |
| 循环边界附近 | 判断元辅音交接位置是否合适 |
| 播放左右组合 | 检查 `ka+at`、`at+ta` 的实际接缝与渐变 |

拖动后可立即重新试听；不应先导出素材或打开另一个软件才能听到结果。

### 3.7 Tag 与审核

tag 完全由用户定义，可用于整个句子，也可用于其中的音节、CV、VC 或局部区间：

- `soft`、`bright`、`strong`、`breathy` 等唱腔/情感；
- `verse`、`take-2` 等来源；
- `good`、`noisy`、`needs-fix` 等个人质量分类。

编辑时支持已有 tag 自动完成、新 tag 创建、批量添加/移除和按 tag 筛选。音素范围、
校对状态和 tag 是不同信息，不把 `ka` 当作 tag 替代结构标记。

审核操作保持简单：`确认`、`待复核`、`禁用`，配撤销/重做和自动保存。重新运行
自动分析不得覆盖人工修改、tag 或禁用状态。

## 4. 制备与校准的分工

| 阶段 | 自动化负责 | 人工界面负责 |
|---|---|---|
| 断句 | 检测自然停顿，提出句子候选 | 合并误拆、重划句段、确认句首句尾 |
| 文本 | G2P 生成音素序列 | 改歌词、多音字、特殊唱法 |
| 音素对齐 | SOFA/STARS 等生成边界草稿 | 波形上拖拽校准、播放验证 |
| 元音与过渡 | 提供元音起点、稳定区和左右关系 | 调整实际可用范围、确认 `ka`/`at` |
| 分类 | 提供音高、时长和自动风险信息 | 打自定义 tag、通过或禁用 |
| 发布 | 校验文件与标记、生成索引 | 决定何时将当前库交给 Ctrl+F 使用 |

自动工具只产生草稿和效率，不让用户从 CSV 数值中猜边界。

## 5. 数据与更新原则

只需坚持以下契约：

1. 每句 WAV 有独立、稳定的配套标记文件。
2. 标记中的时间以该句 WAV 为基准，不依赖整首歌的临时切块编号。
3. 保存音节、音素、元音锚点和左右关系，支持动态构造 `ka`、`at` 及连续子句。
4. tag 同时保存其作用范围，Ctrl+F 才能准确显示和过滤。
5. 保存自动/人工来源与校对状态，人工结果优先且不被重跑覆盖。
6. 修改标记只更新相关文件及搜索索引，不修改 WAV，不触发工程 Clip 重渲染。
7. 禁用范围不作为普通候选返回，但原始音频和标记仍可保留。

具体可用 JSON/JSONL；当前无需设计复杂数据库或服务协议。

## 6. 技术选型

| 部分 | 建议 | 理由 |
|---|---|---|
| 自然断句 | 静音/能量候选 + 人工确认 | 自动提效，避免把短促连唱误断 |
| 中文唱声对齐 | SOFA 先建立基线，STARS 做真实样本对照 | 唱声专用；具体效果以当前歌手与词典验证 |
| 音高与 DSP 辅助 | RMVPE/FCPE；librosa、scipy、numpy 等 | 提供参考与风险，不代替人工边界 |
| 批处理外壳 | 独立 Python CLI | 足以支撑制备，不做过度工程化 |
| 校准 UI | HiFiShifter 内独立“音源校准”工作区 | 复用波形、播放、快捷键和面板基础设施 |
| 标记编辑面 | 新建 `PhraseAnnotationSurface` | 支持播放头与可拖动标记，但不复用 Clip/Take 语义 |
| 标记与 tag | 每句配套 JSON，版本化字段 | 简单、可查看、可备份、可被 App 读取 |
| App 集成 | HiFiShifter 只读已发布音源库 | 模型升级不影响搜索与 Clip 编辑 |

本期不另起校准 App。若将来需要独立分发，可在协议稳定后拆出“校准工作区 + 音频
服务 + 音源协议”；由于标记模型从未绑定工程 Clip，拆分不会改变数据与交互语义。

## 7. 实施顺序

1. **自然断句与逐句文件**：整首纯人声生成每句 WAV、歌词和初始文件索引。
2. **音素草稿**：逐句强制对齐，生成音节、音素、元音与左右关系。
3. **App 内图形校准**：独立工作区、轻量 `PhraseAnnotationSurface`、播放头、
   波形拖拽、范围试听、确认/禁用、独立撤销与自动保存。
4. **自定义 tag**：句子/区间标签、批量编辑、筛选和发布。
5. **接通 Ctrl+F**：验证 `ka`、`at` 搜索及截取结果与校准界面一致。

先完成“断句 -> 校准 -> 搜索”的短闭环，再增加更复杂的模型对照或自动质检。

## 8. 验收场景

1. 输入一首纯人声后，能按自然间隔得到逐句 WAV；误拆句段可在界面合并或调整。
2. 文件列表能看到所有句子的歌词、状态、标记问题与 tag。
3. 用户能在波形上直接拖动 `ka` 或 `at` 的范围，并立即试听，不需要编辑数值。
4. 在 `ka ta` 句中可看到并校准自然的 `a→t`，发布后可被 Ctrl+F 的 `at` 找到。
5. tag 可作用于句子或局部范围，创建、批量修改、筛选后，Ctrl+F 能看到并搜索。
6. 重跑自动对齐不会覆盖人工边界、tag、确认和禁用状态。
7. 修改音源标记不改变 WAV，不触发无关音频处理或工程 Clip 重渲染。
8. 音源工具可以独立运行，HiFiShifter 不需要安装模型即可读取已校准音源库。
9. 拖动音素边界只更新音源标记与播放预览，不调用 Clip 编辑、参数分析或工程渲染。
10. 播放头支持点击/拖动定位、播放跟随和区间循环；校准撤销不进入工程历史。
