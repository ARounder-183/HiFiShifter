# Ctrl+F 连续音选样：句段截取、元音优先与渐变导入

> 状态：按最新需求重写，未实施
>
> 日期：2026-11-10
>
> 配套文档：[独立音源制备与标记校准工具](./2026-11-10-voicebank-slicing-design.md)

## 1. 本期目标

将现有按文件名搜索的 Ctrl+F 升级为“按发音从句段中选区间”的快速工具：

```text
一首歌纯人声
  -> 按自然间隔切成句子，每句一个 WAV + 配套标记
  -> 可选：导入一条 MIDI 参考轨道，提供光标处的音高与时长
  -> Ctrl+F 输入 ka、at 等发音组合
  -> 从句子的标记位置动态截取素材
  -> 查看标签、试听、调整选择
  -> 将选中的素材从当前光标开始拼接导入
  -> 继续按普通 Clip 自由编辑
```

本期不制作歌词音符占位、音符选样任务层或自动排布功能。用户直接从时间轴光标发起
操作，不需要先维护一层歌词工程。

### 1.1 核心原则

1. **音源按句保存，搜索按音截取。** 不把整首歌直接导入，也不提前生成大量单音 WAV。
2. **单音以元音为主体。** `ka` 的搜索围绕元音 `a` 展开，再寻找合适的 `k`。
3. **VC 表示真实衔接。** `at` 优先寻找 `ka ta` 中间自然的 `a→t`，不是两个独立音拼接。
4. **自然连续优先，组合作为补充。** 能从同一句取到完整目标时不做跨来源拼接。
5. **导入后仍是普通 Clip。** 不锁定编辑方式，不引入必须依赖标记层才能使用的音频对象。
6. **MIDI 是可选参考，不是绑定。** 参考轨道提供搜索时的音高、时长和相邻音符，
   已导入 Clip 不跟随 MIDI 自动移动或改调。

## 2. 音源库与搜索对象

### 2.1 音源库的基本形态

```text
voicebank/
├── song-a/
│   ├── 001.wav             # 第一个自然句段
│   ├── 001.marks.json      # 该句的音节、音素、锚点、标签
│   ├── 002.wav
│   ├── 002.marks.json
│   └── ...
├── song-b/
└── library.json            # 音源库说明、版本、歌手与文件索引
```

`ka` 或 `at` 对应某一句 WAV 内的时间范围。多个搜索结果可以引用同一句，不要求
物理生成 `ka.wav`、`at.wav`。

### 2.2 搜索需要的标记

| 标记 | 作用 |
|---|---|
| 音节边界 | 确定 `ka`、`ta` 等单音的自然范围 |
| onset / nucleus / coda | 判断 CV、VC 的发音结构及各自职责 |
| 元音起点、稳定区、尾部 | 元音优先搜索、拍点对齐和元音内部交接 |
| 左右音节关系 | 判断 `at` 是 `ka→ta` 的跨音衔接还是真正 coda |
| 音高、时长 | 候选排序和导入后编辑参考 |
| 自定义 tag | 区分唱腔、情感、音质、录音版本及用户个人分类 |
| 校对状态 | 区分自动草稿与人工确认，过滤不可用区间 |

## 3. 输入 `ka`：以元音为主搜索单音

### 3.1 查询含义

```text
ka = onset k + nucleus a
```

搜索对象主要是自然 CV/单音区间。用户不是只找文件名中包含 `ka` 的文件，而是找
句子中实际可用的 `a`，以及可以与其组合的 `k`。

### 3.2 检索与降级顺序

```text
1. 找最合适的元音 a
   依据音高、可用时长、唱腔/情绪 tag、录音条件和标记质量排序；若选择了 MIDI
   参考轨道，则优先使用光标处音符的音高与时长作为目标。

2. 如果这个 a 自带一致的 onset k
   直接截取自然 ka，作为首选，不做组合。

3. 如果没有，寻找其他元音同为 a 的 k
   优先同一歌手、同一录音/相近唱腔；用该 k 的 onset 替换或接到所选 a 前面。

4. 如果仍没有，寻找元音相似的 k
   例如发音动作、开口度和音色相近的元音环境；界面明确标出实际来源，不冒充自然 ka。

5. 如果仍没有，再找其他可用的 k
   作为最后降级，标明跨元音辅音组合及潜在不自然风险。
```

这里的第 3～5 步寻找的是**处于某个元音语境中的 onset k**，不是假设孤立辅音文件
必然存在。最终仍应优先得到“k + 目标 a”的可试听候选。

### 3.3 同元音优先于表面相似度

音素匹配是硬条件，音高、音色和 tag 用于同级排序。不得因为某个候选音色很像，
就把错误的元音排到自然 `ka` 前面。

没有自然 `ka` 时，结果按以下分组展示：

```text
自然 ka
同元音 a + 其他 a 语境的 k
相似元音语境的 k + 目标 a
其他语境的 k + 目标 a
```

用户可以看到每个组合“元音来自哪里、辅音来自哪里、为什么这样推荐”。

## 4. 输入 `at`：寻找自然的元音到辅音衔接

### 4.1 查询含义

本期 `at` 主要指：

```text
ka ta
 [a→t]
```

即前一个元音 `a` 的尾部受到后一音节 onset `t` 影响的自然变化。搜索时利用句子的
音素序列和音节归属找到这种位置，而不是只搜索相邻字母 `at`。

例如一句自然演唱 `ka ta`，可以截取其中的 `at` 作为过渡素材；如果整句为
`katana`，也可以从相同位置取得 `at`，供其他 `ka / ta` 组合使用。

### 4.2 标记和展示

候选需要显示：

- 来源句子和原始左右音节，例如 `ka ta`；
- 截取范围在句子中的位置；
- 元音 `a`、后续 onset `t` 和可用过渡长度；
- 自定义 tag 与校对状态。

本期默认只将这种**跨音节 VC 衔接**用于 `at` 查询。真正音节内 coda 的语义保留在
协议中，但不扩展成新的歌词音符或自动排布系统。

## 5. 组合规则：两个 V 不重复，共享 C 不重复

### 5.1 同一句中的相邻素材

如果用户选中的 `ka / at / ta` 来自同一句且区间相邻兼容，优先直接使用该句的
连续范围，避免无意义的拆分再拼接。

### 5.2 `CV + VC`：在元音内部交接

以 `ka + at` 为例：

```text
ka：k + a 的主体 ───╮
                    ├─ a 尾部渐变交接
at：                 ╰─ 受 t 影响的 a 尾部 + t
```

`ka` 提供 onset 和元音主体，`at` 提供元音尾部与后续 `t`。同一个 `a` 只形成一次
连续发音，不是播放完完整 `ka` 后再播放一个完整 `at`。

CVC 同理：CV 提供 onset 和元音主体，真正 coda VC 提供受韵尾影响的元音尾部。
不应只用 CV 的元音再接孤立辅音，也不应长时间叠加两个完整 V。

### 5.3 `VC + CV`：在共享辅音区域交接

以 `at + ta` 为例：

```text
at：a→t 的衔接 ───╮
                  ├─ t 区域渐变交接
ta：               ╰─ t + 后一个 a
```

两个视图都可能包含 `t`，但最终只保留一次 `t`。切割位置应参考共享辅音的标记，
不能将两个完整区间简单首尾相连。

### 5.4 渐变的目的与限制

渐变用于平滑实际接缝、减少爆音和音色突变，不是用来掩盖错误发音。默认使用短交叉
渐变，并允许用户试听和调整。不同音素、不同边界类型不能机械套用一个固定时长。

## 6. Ctrl+F 交互流程

### 6.1 MIDI 参考轨道

#### 6.1.1 定位

用户可以用现有 MIDI 导入功能，将 MIDI 音符放到一条普通轨道中，并在 Ctrl+F 里
将其选为参考轨道。它只回答“当前光标处希望唱什么音、持续多久”，不引入歌词音符
占位，也不要求音频 Clip 与 MIDI 建立持续绑定。

参考轨道选择可跨多次 Ctrl+F 保持记忆。未选择参考轨道时，现有文件/音源搜索照常
工作，不要求用户为了搜索素材而准备 MIDI。

#### 6.1.2 打开时读取的上下文

```text
参考轨道：主旋律
光标：00:12.500
命中音符：D4，00:12.250 - 00:12.750，持续 0.50s
当前光标处于音符中段，剩余 0.25s
相邻音符：前一音 C4，后一音 E4（用于时长与衔接提示）
```

搜索 `ka` 时，MIDI 信息用于同级候选排序：

- 元音音高接近 D4、所需移调较少的候选优先；
- 候选显示原始音高与目标音高，例如 `C4 -> D4 / +2st`；
- 元音可用时长接近目标的候选优先，明显需要拉伸的候选给出提示；
- 相邻音符用于判断当前音可用的起音、尾音和过渡空间，不自动决定歌词。

#### 6.1.3 对齐与时长语义

| 选择 | 行为 |
|---|---|
| `当前光标`（默认） | 元音有效起点对齐当前光标，参考音符只提供音高与时长 |
| `音符起点` | 元音有效起点对齐命中音符的起点，onset 可提前 |

光标在音符中段时，不默认偷偷回到音符起点。选择“音符起点”后若未启用“导入后
移动光标”，光标保持原位，便于继续检查和选择。

MIDI 音符时长不是纯元音时长。它可能还包含 onset、元音尾部及向下一个音的过渡：

```text
目标元音时长参考
≈ MIDI 音符时长 - onset 占用 - 后续衔接空间
```

本期将它作为排序和试听提示，不自动强行拉伸或裁切到该数值。用户选择 `at` 等过渡时，
相邻 MIDI 音符的起点和间隔可用于提示过渡需要占据的时间。

#### 6.1.4 边界情况与解耦

- 光标处没有 MIDI 音符：显示“当前无参考音符”，正常搜索，不隐藏候选。
- 光标处存在多个重叠音符：显示歧义，让用户选择；不默认取最高音或第一条。
- 参考轨道缺少音符数据：提示重新导入/更新该 MIDI Clip，不伪造音高。
- 修改 MIDI 不自动移动、改调或拉伸已导入 Clip；重新打开/刷新 Ctrl+F 才读取新上下文。
- 选择参考轨道本身不触发音频分析或重渲染。

### 6.2 基础流程

```text
光标放到目标位置
  -> Ctrl+F，输入 ka 或 at
  -> 可选：选择 MIDI 参考轨道，读取光标处音高、时长和相邻音符
  -> 选择“当前光标 / 音符起点”作为元音对齐位置
  -> 显示发音解析、可用 tag 筛选和分组候选
  -> 上下选择候选，空格试听截取结果/实际接缝
  -> 回车，按所选“当前光标 / 音符起点”对齐并拼接导入
  -> 需要精修时，直接编辑时间轴 Clip 的入口、出口、渐变、音高和时长
```

保留现有文件名搜索模式。发音无法解析、音源库未配置或索引不可用时，明确提示并允许
回退到文件搜索。

### 6.3 连续选择

用户可依次执行：

```text
Ctrl+F ka -> 回车
Ctrl+F at -> 回车
Ctrl+F ta -> 回车
```

每次导入按所选的“当前光标 / 音符起点”确定元音位置。若用户希望连续向后放置，
可在弹窗中选择“导入后光标移到拼接内容末尾”；关闭该选项时，后续操作仍从原光标
开始，由用户自行管理重叠。MIDI 参考不改变这一光标选项。

不要求使用歌词音符层，也不自动推断用户下一次要输入什么。

### 6.4 标签筛选与搜索

tag 是用户自定义的一等信息：

- 候选行直接显示主要 tag；
- 可按一个或多个 tag 过滤；
- 支持 `#tag ka`、`ka #soft` 等形式；
- 单独输入 `#soft` 可浏览该标签下的素材；
- tag 只帮助区分和筛选，不改变 `ka` 的音素含义。

标签可以是 `soft`、`strong`、`breathy`、`bright`、`good`、`take-2` 等任意用户
习惯用语，不要求系统预置完整分类体系。

### 6.5 键盘优先：只走“查、听、选、放”

#### 6.5.1 交互目标与边界

Ctrl+F 是一个短路径选择器，不是音频编辑器。精细调整入口、出口、渐变、音高、
时长等全部交给导入后的 Clip 与轨道面板；弹窗内不增加波形精调模式、数值编辑框
或多级设置页面。

键盘流的核心是：

```text
Ctrl+F -> 输入 -> ↓/↑ -> Space -> Enter -> 继续 Ctrl+F
```

所有高频操作都在搜索输入框内完成，用户不需要 Tab 到列表、点击候选、点试听按钮
或点击导入按钮。鼠标只是可选补充，不能成为任何功能的唯一入口。

#### 6.5.2 默认键盘地图

| 按键 | 行为 |
|---|---|
| `Ctrl+F` | 打开，保留上次的音源库、参考轨道和筛选；新查询默认全选，直接输入即替换 |
| 普通字符 / Backspace | 编辑查询；焦点始终留在输入框，不因移动候选而跳转 |
| `↓ / ↑` | 选择下/上一个候选；到末尾/开头时循环，分组标题不占候选位置 |
| `Ctrl+J / Ctrl+K` | 与 `↓ / ↑` 相同，适合双手不离开字母区的连续操作 |
| `PageDown / PageUp` | 按可见候选数量翻页，保留列表滚动位置 |
| `Home / End` | 跳到第一/最后一条候选 |
| `Alt+→ / Alt+←` | 展开/折叠当前分组，或切换当前组合候选的元音/辅音来源 |
| `Space` | 播放/停止当前候选；再次按下从头播放当前选择 |
| `Shift+Space` | 播放/停止当前候选的工程上下文 |
| `Alt+Space` | 在“原始截取 / 实际组合”试听之间切换并立即播放 |
| `Enter` | 导入当前候选并关闭；一次导入一条撤销记录 |
| `Shift+Enter` | 导入当前候选、保持弹窗打开并全选查询；直接输入即替换，方向键编辑原查询 |
| `Ctrl+Enter` | 导入当前候选、关闭并立即重新打开，准备连续选下一个 |
| `Esc` | 有播放时先停止；无播放时关闭弹窗 |

这些新增按键应注册到现有 `quickSearch` 作用域，不与时间轴导航、播放或编辑快捷键
同时生效。保留用户自定义键位的能力；表中为默认行为。无修饰的 `← / →` 始终用于
编辑查询文本，不占用常见的输入行为。

`Enter` 默认遵守“导入后移到内容末尾”的既有选择；`Shift+Enter` 导入后按该选项
更新光标、保留 MIDI 参考和筛选，但不延续旧候选选中态，防止误把下一项重复导入。

#### 6.5.3 少按键的查询与筛选

- `ka`、`at` 输入后立即搜索，无需额外回车。
- `#soft ka` 与 `ka #soft` 都直接作为查询，不要求打开 tag 面板。
- 输入 `#` 时展示可用 tag 补全；此时 `↓ / ↑` 选择补全，`Tab` 接受补全，`Esc`
  先关闭补全；没有补全时这些按键保持候选导航/停止/关闭的常规含义。
- `Ctrl+Backspace` 删除一个查询词或一个完整 `#tag`，快速收窄/放宽筛选。
- `Alt+R` 循环切换 MIDI 参考轨道：无参考 -> 最近使用 -> 其他含 MIDI 的轨道。
- `Alt+A` 在“当前光标 / 音符起点”间切换；`Alt+D` 开关时长参考。
- 参考轨道、对齐方式、是否自动试听等偏好跨弹窗记忆，不在每次打开时重置。

无 MIDI 音符时，`Alt+A / Alt+D` 不改变其他搜索状态，只在上下文行显示原因。

#### 6.5.4 选择即预览，但不能打扰

- 打开时不自动出声。
- 输入搜索期间不自动试听，避免每个字母都触发音频切换。
- 搜索结果稳定后，若开启“选择即试听”，`↓ / ↑` 停止旧试听并播放新区间。
- 关闭“选择即试听”时，仅用 `Space` 主动试听；偏好可记忆。
- 新搜索发起后停止不再匹配的试听；旧请求后返回不能覆盖新候选或抢占播放。
- 切换候选只更新详情，不展开额外面板、不移动输入焦点、不重置列表滚动。

#### 6.5.5 连续选样的最短路径

```text
Ctrl+F  ka   ↓   Space   Shift+Enter
at               Space   Shift+Enter
ta        ↓↓   Space   Enter
```

第一次导入后弹窗保持打开，用户直接输入 `at`；第二次后继续输入 `ta`；最后一次
关闭。全程不需要鼠标，也不需要为了精调进入另一个模式。

弹窗关闭后回到时间轴并选中刚导入的 Clip。需要精修时，使用现有轨道/Clip 键盘
操作处理，不在 Ctrl+F 内复制一套 Clip 编辑器。

#### 6.5.6 状态与可预期性

- 输入框拥有唯一主焦点；组合框保留 `aria-activedescendant` 表达当前候选。
- 每个候选的稳定身份由素材 ID 决定，列表刷新尽量保留同 ID 选中项。
- 列表为空、加载、无参考音符、解析失败和索引过期是不同的可见状态。
- `Enter` 只在有可用候选时生效；加载中不重复提交，导入失败保留当前选择。
- `Esc` 关闭不修改工程，停止试听不移动播放头。
- 所有操作都可通过键盘完成，不让悬停 tooltip 承载必须知道的信息。

## 7. 界面草稿

```text
┌───────────────────────────────────────────────────────────────────────┐
│ [文件 | 音源]  ka #soft                          singer-a · 中文     │
│ 参考：[主旋律 ▾]  D4 · 0.50s   对齐：[当前光标 ▾]  时长参考：[✓]    │
├────────────────────────────────────┬──────────────────────────────────┤
│ 自然 ka                            │ song-a / 003.wav                │
│ ♪ 003 · 00:03.12  C4->D4  soft    │ ... [ka]  ta ...                │
│ ♪ 017 · 00:11.40   C4   soft      │       ╰当前截取                 │
│                                    │ 元音 a · onset k · 已校对       │
│ 同元音组合                         │ tag：[soft] [clear] [verse]     │
│ ◇ a / 003 + k / 008   同录音       │                                  │
│                                    │ [原区间] [当前组合] [工程上下文] │
│ 相似元音的辅音组合                 │ 原区间含自然接缝                 │

│                                    │ 元音 0.36s / 参考 0.50s          │

```

`at` 的详情改为突出 `a→t` 的原始上下文：

```text
来源：song-a / 003.wav / ka ta
范围：       ka [══ at ══] ta
说明：自然 a→t 衔接；与 ta 组合时在共享 t 区域交接。
tag：[legato] [soft] [checked]
```

## 8. 拼接与导入

### 8.1 光标处的行为

- 选中的首个元音锚点对齐当前光标，或用户明确选择的 MIDI 音符起点；onset 可以自然
  位于目标位置之前，因此实际 Clip 起点可能早于目标位置，界面需显示这一结果。
- 多个选中部件从当前目标位置开始形成一个连续选段，内部使用所需渐变。
- 渐变产生的重叠只改变相邻素材的交接，不再额外向前移动已对齐的元音锚点，也不把
  内容尾部的渐变延伸到下一个尚未选择的位置。
- 一次导入产生一条撤销记录。
- 目标位置已有 Clip 时不默认删除；覆盖、插入或另开轨道沿用现有导入交互规则。

### 8.2 导入后

结果是普通 Clip，保留源 WAV、源区间、淡化及现有参数编辑能力。用户可以移动、裁切、
拉伸、拆分、替换或删除，不需要回到音源标记工具才能继续编辑。

Clip 可保留来源标记的只读引用，便于知道来自哪句、哪个发音；修改 Clip 不反向修改
音源库，删除 Clip 也不影响音源库。

MIDI 参考轨道与 Clip 不建立持续控制关系。导入时只使用当时读取的音高、时长和对齐
选择；后续修改参考 MIDI 不自动改动已导入 Clip。

## 9. HiFiShifter 性能检查

以下结论来自当前 `develop` 工作区的静态代码检查（`7d373ae9`），未做运行基准。

### 9.1 结论

**按句保存、频繁从同一句截取多个 Clip 的路线可行，现有架构已有不少直接支撑。
不会因为一个句子被引用多次就天然需要解码多次，但组合试听和渲染缓存需要专门处理。**

### 9.2 已有优势

| 路径 | 当前能力 | 对本需求的意义 |
|---|---|---|
| Clip 源窗口 | `source_start_sec/source_end_sec` 已参与播放和渲染 | 同一句 WAV 可直接承载多个截取区间 |
| 实时解码 | ResourceManager 按 `(path, sampleRate)` 缓存整文件 PCM，并对在途解码去重 | 同句多个 Clip 可共享解码结果 |
| 原始音高/电平 | 按源内容身份共享分析，trim/rate 在组装时截取 | 同句截取通常不需重新跑全量音高分析 |
| 波形 | 按源文件做 mipmap，内存/磁盘缓存并支持批量预载 | 同句的多个 Clip 可复用波形数据 |
| 导出 | 对多次引用的源路径做当次混音解码去重 | 频繁引用句子已有针对性优化 |

相关实现位置：
[resource_manager.rs](../../../backend/src-tauri/src/audio_engine/resource_manager.rs)、
[pitch_clip.rs](../../../backend/hifishifter-kernel/src/pitch_clip.rs)、
[waveformMipmapStore.ts](../../../frontend/src/utils/waveformMipmapStore.ts)。

### 9.3 需要补齐或关注的风险

**1. 当前文件试听不是任意区间试听。**

现有 `read_audio_preview` 读取音频前缀，Web Audio 从缓存 buffer 的开头播放。
它不能直接满足“从句子中间截取 `ka`/`at`”，需要新增区间读取，或在缓存整句后
用 `AudioBufferSourceNode.start(when, offset, duration)` 播放指定范围。不能让候选
仍从头播放整句。

**2. 同一句的原始播放共享 PCM，但处理后的 Clip 不一定共享。**

源窗口、时长、音高曲线、拉伸等会进入 Clip 级渲染键。选取同一句的不同位置或
反复调整接缝时，需要重新渲染是合理行为，不能为了复用而误用旧音频。渐变试听可
先走轻量原声组合预览，最终再用实际处理链复核。

**3. 整句 PCM 是整文件缓存。**

句子通常比整首歌短很多，因此“先断句成文件”本身就能降低单文件解码和缓存压力。
但大量不同句段仍受缓存字节预算约束；只预载当前浏览和近期使用的句段，不应因为
建立索引就把全库 WAV 全部解码。

**4. 快照重建仍存在按 Clip 遍历和文件元数据检查。**

大量短 Clip 会带来额外遍历、哈希和元数据查询。当前实现有按文件解码缓存，但快照
中的部分校验仍按 Clip 执行。本期不必先重构渲染器，实施后用真实短 Clip 工程验证。

**5. 校对器的标记操作不应触发音频重渲染。**

修改标记、tag 或校对状态只更新音源索引和界面。只有已经导入工程的 Clip 被用户
主动替换时才改工程音频；不能因保存标记而让整库或当前工程重渲染。

### 9.4 实现约束与验证

- 搜索只加载轻量标记，不解码全库音频。
- 区间试听按句缓存/复用，快速切换时取消过期播放会话。
- 同一句的波形、解码、原始音高分析继续按源文件复用。
- 导入使用已有源窗口和普通 Clip，不为每个搜索视图生成新 WAV。
- 标记与 tag 的保存不触发 Clip 渲染。
- 参考轨道只读取 MIDI 音符；切换参考或修改 MIDI 本身不触发音频 Clip 重渲染。
- 最终用“同一句多个区间 + 多个不同句段 + 短 Clip 渐变”场景做播放、滚动和
  连续试听验证，再决定是否需要进一步按文件合并元数据检查或优化预览缓存。

## 10. 本期实施顺序

1. **读取句段音源库**：识别每句 WAV、音素标记、tag 和校对状态。
2. **读取 MIDI 参考上下文**：选择轨道，按光标解析音符音高、时长和相邻音符。
3. **Ctrl+F 发音搜索**：先支持自然 `ka` 和句内跨音 `at`，保留文件模式。
4. **键盘优先的区间试听与渐变导入**：从句中截取，按光标或音符起点生成普通 Clip；
   弹窗只负责查、听、选、放，精修交给 Clip。
5. **组合降级**：为缺少自然 `ka` 的情况加入同元音、相似元音和其他语境的 onset 候选。
6. **性能验证**：覆盖同句多区间、多句快速试听、组合预览和大量短 Clip。

本期不依赖歌词音符占位；整句/多音连续候选和更复杂自动链式编排可作为后续增强。

## 11. 本期验收

1. 一句 `ka ta` 只需一个 WAV 和配套标记，就能搜索、试听和截取 `ka`、`at`、`ta`。
2. 搜索 `ka` 先返回自然匹配；没有时按同元音、相似元音、其他语境顺序降级。
3. 搜索 `at` 能找到 `ka ta` 的自然 `a→t` 衔接，而非仅匹配文件名。
4. tag 能在候选中看到、筛选和直接搜索。
5. `ka + at` 不重复元音，`at + ta` 不重复辅音，接缝有渐变且可试听。
6. 选中素材从当前光标处拼接导入，一次操作可撤销，导入后 Clip 可自由编辑。
7. 同一句多次截取不重复建立全库解码任务，试听真正播放选中的区间而非句首。
8. 修改音源标记或 tag 不导致工程内无关 Clip 重渲染。
9. 选择 MIDI 参考轨道后，`ka` 同级候选优先匹配光标处音符音高，并显示预计移调量。
10. 光标位于音符中段时默认仍对齐光标；仅选择“音符起点”才按音符起点放置。
11. MIDI 时长只作为元音时长参考，不自动强拉伸；无音符或重叠音符有明确反馈。
12. 修改参考 MIDI 不自动改动已导入 Clip，Clip 的原有自由编辑能力保持不变。
13. 全程无需鼠标即可完成输入、候选选择、tag 筛选、原区间/组合/上下文试听、导入
    和连续下一次选择；弹窗不提供 Clip 精调数值编辑。
14. `Shift+Enter` 导入后保留上下文并允许直接输入下一查询，关闭后回到时间轴 Clip。
