# 音源编码与 UST 数据保真

公开版本为 0.25，本次文档内部编号 058。

## 音源编码

在音源库 OTO 列表上方使用“目录读取编码”：先选音源根目录或含 oto.ini 的子目录，再选自动、UTF-8、Shift-JIS、GBK、Big5 或 GB18030。目录选择单独保存到该目录的 `hachi-encoding.json`，仅改变读取方式，不批量转换文件。UTF-8 BOM 与明确的 UTF-8 声明优先。

编辑器和渲染器共用读取逻辑，涵盖 oto.ini、oto.jie.ini、oto4.ini、otomou.ini 和 prefix.map。自动识别会参考有效字节、日文假名及实际存在的采样文件名；短文本或纯汉字可能有歧义，遇到乱码请指定原编码。更改目录设置后立即重读音源索引。

编辑经典 OTO 条目保持原编码、BOM、换行、空行、未修改数值的写法及额外列；只改需要改的字段。文字无法在原编码中表示时拒绝写入，不替换成问号。OTO 列表读取后若文件被其他程序修改，保存会提示刷新，避免用旧条目覆盖新内容。写入使用同目录短文件名临时文件，刷新并回读校验后替换，避免长路径音源在生成嵌套临时文件时失败。新建界 / 谋 OTO 继承目录或原 OTO 编码；已有文件按各自读取编码写回。

## UST 导入和工程保存

“文件 → 导入 UST”先选择文件，再在导入窗口选择编码。自动识别不正确时可以指定编码重新导入；向现有工程添加轨道仍采用现有工程的速度图。

导入时保留源文件全文、原始字节、编码、BOM、每个音符的原始段及编辑基准。这些资料随 HJPX 保存、重开和撤销；不依赖原 UST 仍留在原路径。未知字段、未知区段、空字段、休止符及未启用的 Mode 1/2 数据不再在转换时丢弃。未知区段不会被误当作音符。

补齐 Mode 1 的 PBStart、PitchBend / Pitches：PBStart 按毫秒，曲线每 5 tick 一个采样，音高按 cents；优先使用当前音符的数据，负时间范围可继承前音符。Mode2=True 时使用 Mode 2 与 VBR，Mode2=False 时保留但不启用 Mode 2/VBR。原始 Modulation 与 STP 随工程保存；Modulation 传给外部重采样器的调制参数，STP 使用现有采样偏移功能。UST 包络按线性振幅插值。

## UST 导出

“文件 → 导出当前轨道 UST…”导出当前选中的一个音符轨道，可保持原编码或另选上述编码。新轨道默认 UTF-8。支持 MCP `export_ust` 的同一条导出路径。

- 未修改且保持原编码的导入工程，导出保留原始字节，包括 Shift-JIS 的重复字符编码写法。
- 只修改歌词、音高、FLAG 或时序参数时，只更新对应字段，其他原文字段保留；Mode 1 与 Mode 2 未启用的数据继续保留。
- 改变音符布局或速度后，重建音符编号、休止符和速度位置；原休止符的附加字段仍保存在 HJPX 导入原文中，导出会提示该差异。
- 同轨重叠音符、负位置、不到 1 tick 的音符以及音符中间变速不能直接表示为单声部 UST，会拒绝导出并提示处理方式。
- 自定义响度包络无法表达为标准 UST 包络时拒绝导出。自定义 Bezier 音高区间按 5 ms 近似为线段；标准 UST 包络按线性振幅播放。
- 标准 UST 不包含 DS 预测资料与偏移、线性 / 分区 FLAG、独立 OTO、高级尾段淡出和编辑器自动过渡等全部功能。导出会提示相应限制；完整工程继续使用 HJPX 保存。

这里保证的是来源数据留存和受支持字段的交换，不承诺不同重采样器、UTAU / OpenUtau 与本编辑器的混音完全相同。旧 HJPX 没有保存过的原始 UST 字段无法凭空恢复；需要重新导入原 UST 才能建立原文基准。

## MCP

- `import_ust`: `path`，可选 `encoding`，支持 `auto / UTF-8 / Shift-JIS / GBK / Big5 / GB18030`。
- `export_ust`: `path`、`track_id`，可选 `encoding`。`auto` 或不提供表示保持原编码。
- 连接当前窗口时按既有规则提供 `expected_revision`；导出完成不会改变音符、撤销历史或未保存状态。
