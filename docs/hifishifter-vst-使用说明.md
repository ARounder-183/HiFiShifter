# HiFiShifter VST 使用说明

适用：Windows x64、REAPER、HiFiShifter ARA/VST3 插件。当前研发包仍在集中验收，
以下是操作说明，不是所有功能已通过实机验收的承诺。独立 App 仍可照常使用，插件
不需要先启动独立 App。Linux/macOS 插件不在本次范围。

## 安装与打开

1. 关闭 REAPER，将**整个** `HiFiShifter.vst3` 文件夹放入一个 VST3 目录，或把其父目录
   加入 REAPER 的 VST 扫描路径。不要只复制里面的单个文件；界面、模型和运行依赖
   必须随整个文件夹一起保留。Windows 需安装 WebView2 Runtime 与 VC++ x64 运行库。
2. 重新启动 REAPER 并扫描插件，在有人声音频片段的轨道上添加 VST3 HiFiShifter。
   用宿主的 ARA 模式，不是把声音导入独立 App。建议先用工程副本试用新版本。
3. 要接入多条轨道，在各条需要处理的轨道上分别添加插件。打开任意一个 HiFiShifter
   窗口即可编辑同工程已接入的多轨；不是把全工程混音复制回每条轨。不同工程不共享编辑。
4. 操作快捷键前先点击插件窗口，使键盘焦点进入界面。

## 编辑与播放

音频导入、片段位置、裁切、线性拉伸、BPM 和宿主渐变在 REAPER 中调整；音高曲线、
气声、张力、共振峰等在 HiFiShifter 原界面中编辑。先选中目标轨道或片段，再编辑参数。
同一工程的多个 HiFiShifter 窗口是同一个工作区的视图，不是独立编辑副本。

编辑会后台自动应用。顶部显示“等待宿主音频”“正在自动应用…”或“已应用”；重模型
首次处理可能较慢。只有就绪后的音频才替换当前输出，不把尚未完成的渲染当成功。
宿主提供控制能力时，界面的播放/暂停控制 REAPER；播放头以所属工程的位置为准。

通常不需要点击“重新载入宿主”。发生模型/权限冲突或“尚未应用”时，先查看错误；
若仍有未应用曲线，重载会要求确认，因为可能替换本地编辑。不要把重载当日常提交按钮。

## 保存与重开

在 REAPER 中保存工程，插件参数随工程保存。关闭插件窗口不会删除编辑，也不需要
让独立 App 常驻。重开工程后等待源授权与后台准备；离线导出走宿主准备流程。
不要在 REAPER 仍运行时覆盖已加载插件，升级前保存并关闭宿主。

## 限制与常见问题

- 当前支持范围是正向、**线性**拉伸；倒放、拉伸标记等非线性变化暂不支持。
- 普通渐变的声音由 REAPER 应用一次。界面自动读取宿主的渐变长度与参数，曲线和
  波形使用 HiFiShifter 自己的示意包络，不要求与 REAPER 曲线逐点一致。
- HiFiGAN 分块推理；HNSEP 按整段分离，长素材开启气声/张力可能需要很多内存。
  “HNSEP整段处理内存不足”表示未启动巨型推理，效果没有被静默忽略。缓存命中可复用，
  但不能用快照的 512 MiB 额度来判断模型的全部内存成本。
- 找不到插件：检查复制的是整个 VST3 文件夹、REAPER 扫描路径和运行依赖。
- 等待音频或无法分析：检查轨道是否有有效音频、插件是否以 ARA 接入及顶部错误。
  宿主未授予样本读取权限时不能用本地文件冒充宿主源。
- 参数未生效或保存后不一致：保留工程副本和顶部错误信息，先不要覆盖工程或反复强制
  重载；这类情况仍须以最后一次集中实机验收判断是否关闭。

构建和后续开发同步见同目录的 `ara-build-and-sync.md`，本文件只说明使用方法。
