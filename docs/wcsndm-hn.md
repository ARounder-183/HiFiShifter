# WCSNDM HN 实验模式（0.25 · 更新 178）

WCSNDM 版本保持 0.0803。选择 WCSNDM 输出引擎，在音符或轨道的固定 Flags 中只填 `HN1` 才会选择该内核。`HN`、`HN0`、`HN2` 等不受支持的值不会开启，也不会占用内核选择位置。去掉 `HN1` 后，可改选 `HF2`、`V1`、`V2`；未指定内核时仍默认 HF2。不要把 HN1 作为线性 FLAG 曲线绘制。

HN1 与 HF2、V1、V2、K/L/M 的内核并列且互斥，共用“第一个有效内核选择生效”的规则。例如 `HN1V2` 使用 HN1，`V2HN1` 使用 V2，`HF2HN1` 使用 HF2。`HNHN1`、`HN0HN1`、`HN2HN1` 均选择 HN1，因为前面的无效 HN 值被忽略。直接原音输出 `u` 保持原有优先级。

## 实际信号路径

1. 完整原始采样由现有 HiFisampler 的 HN-SEP ONNX 模型分离，只取谐波波形；不混入它的噪声残差。
2. 对谐波波形做 2048 点 Hann STFT，并按 WCSNDM 已有 `remap[j]` 对功率谱做时间插值。HN-SEP 自身使用上游周期 Hann；转换到当前 WCSNDM 频谱时使用其原有对称 Hann 增益。
3. 对支持的谐波 FLAG，复用 C 端 `apply_flags_to_frame`／`apply_mq_to_frame` 得到编辑前后声道包络差值。Mt/Rd 还叠加与 LLSM 同一 LF 模型、同一首谐波归一化规则的声门谱比值；使用源 F0 计算，不移动实测谐波或目标音高。将 dB 差值转为 `10^(dB/10)`，只乘 HN 谐波功率。零参数严格为单位增益；不引入原 LLSM 默认自动高频倾斜。
4. 使用 LLSM 编辑后的非谐波 PSD，沿用 PSDRES、频谱分辨率、噪声 FLAG 和时间映射。
5. 在线性 FFT 功率域相加，再开方、经过同一 Mel 滤波器组、取 log；沿用现有声码器输入的整体均值对齐与限位。不是两张 log-Mel 直接相加。
6. 将该 Mel 和当前目标 F0 送入 PC-NSF-HiFiGAN，再使用既有输出音量、归一化及后处理。HN 使用整段神经重建，不走 HF2 的 V2 辅音拼接。

源谱保留原始谐波位置，变调由现有 PC-NSF 的目标 F0 条件完成；拉伸共用源时间映射。这个实验旨在比较“实测谐波 STFT”与“LLSM 离散谐波重建”的差异，不代表全音域音质已经优于原模式。

## 支持范围与限制

- 非谐波相关 FLAG（如 Mb）和输出阶段的音量、包络继续使用原链路。
- 已支持下表的谐波参数，固定 FLAG、分区 FLAG、线性 FLAG 包络复用同一逐帧取值。源帧无有效有声音高或声道包络时，该帧不施加这些谐波编辑。
- 仍未接入其他谐波侧参数（例如 Mf、MH、A、bh、RG 的谐波部分、相位／时序正则化）；FC/OD 被绕过，日志注明。不要把本次支持理解为全部 FLAG 已等效。QX/ME 按原有定义同时编辑 LLSM 噪声谱，其他新增的七类只修改谐波。
- HN-SEP 与 LLSM 对谐波/噪声的划分可能不同，混合后可能有成分重复或缺失，需要试听判断。不是严格的原音重建。
- HN 不支持分离分轨导出；编辑器会阻止把 HN 误认为 K2 的可分离输出。
- HN-SEP 模型缺失、输入或映射无效时返回合成错误，不静默换回旧谐波路径。
- 模型在后台首次使用时加载；源音频按内容哈希缓存谐波波形，最多 16 项、64 MiB。模型文件变化会使缓存失效，不在用户音源目录新建 HN 缓存。

## 共享分离缓存（更新 178）

Windows 默认目录 `%LOCALAPPDATA%/HachiShifter/cache/hnsep-v1`，可用 `HACHISHIFTER_HNSEP_CACHE` 覆盖。不往音源目录写缓存。磁盘预算 512 MiB，按最近使用时间清理本目录 `.hnh`；单项超过 64 MiB 仍合成但不落盘。HN1 原有 16 项／64 MiB 内存缓存保留。

仅缓存完整、未经变调／拉伸／FLAG／包络处理的谐波波形。两条引擎保留原有声道选择及重采样行为；实际输入 PCM 相同才互用，输入不同则各自计算。

身份串依次是分离算法版本、采样率、FFT、hop、样本数、模型文件 SHA256、原始配置文件 SHA256、实际输入小端 float32 PCM SHA256，每项以换行结尾，再取 SHA256。同大小、同时间戳替换 PCM 或模型仍失效；路径移动不失效。仅 WAV 元数据改变而实际 PCM 不变时可复用。模型会话从参与哈希的模型字节快照加载，Python 音频从此次读取的字节快照解码，避免内容身份与实际输入不符。缓存命中无需创建 HN-SEP 会话。

`.hnh` 格式：8 字节 `HNHARM1\n`、64 字节身份十六进制、8 字节小端样本数、64 字节 payload SHA256，随后为 float32 波形。读取校验身份、长度、内容摘要和有限数值；损坏／截断／旧格式重算。Windows 同名内核互斥锁覆盖读取、分离及发布，进程异常退出自动释放。唯一临时文件完整写入后替换目标。G 和 Python `separate(..., force=True)` 跳过内存、磁盘缓存并重算。缓存不可写时正常推理，不切换声音算法。

本规则位于分离层，不改变上层工程音频缓存的刷新入口；若工程层未重新发起分离请求，仍沿用现有刷新／G 强制重算语义。

协议入口是 C++ `backend/HnsepDiskCache.inc` 与 Python `hf_backend/hn_cache.py`；既有 `hifiSeparate`／`hn_mel.separate` 接入，不新增服务。`--smoke-hn-cache` 由 `src/test-hn-cache.py` 调用进行跨语言验证；`src/test-hn-cache-render.py` 验证 HN1 服务重启后仍能复用编辑器预热结果。报告在 `test-output/update178/`。测试信号的独立 C++／Python 分离最大逐采样差 `5.96e-8`，缓存读取逐字节一致；不宣称不同设备独立推理逐字节相同。

## 可用谐波参数

| FLAG | 范围 | 作用 |
|---|---|---|
| `g` | −50～50 | 共振峰整体移动，正值降低、负值升高 |
| `Mo` | −100～100 | 开口度，主要改变 1800 Hz 以下声道包络 |
| `QX` / `ME` | −100～100 | 正值锐化谱峰，负值平滑；两者是同一参数别名 |
| `Mr` | −100～100 | 增强／减弱约 3 kHz 共鸣 |
| `Mq` | 0～100 | 衰减 3 kHz 以上高次谐波，数值越大越暗 |
| `Mt` | −100～100 | 张力，组合声门 Rd 与谱倾斜；正值偏紧亮 |
| `Rd` | −100～100 | 单独调整声门 Rd，正值减小 Rd；不是直接指定 Rd 数值 |
| `NA` | −100～100 | 鼻音相关峰谷调整 |

例如 `HN1g15Mt20Mq25` 同时启用 HN1、共振峰调整、张力和高频衰减；只填 `HN1` 为原始实验音色。全部参数默认零，超过范围按既有 WCSNDM 参数范围限位。`HN2` 不是新的用户开关，单独填写不会启用 HN。

这里传递的是 LLSM 估算出的频谱包络变化，再由神经声码器重建；并非直接改变 HN 波形相位，因此不承诺与传统内核相同数值的听感完全一致。

## 维护入口

当前外置引擎源码：`../../WCSNDM-0.0803-Windows-x64/src/llsm_utau.c`。

- `parse_flags`：HN 内核选择。
- HF 参数导出：额外导出源毫秒时间映射及 1025 个 FFT 频点的谐波增益（同一 CSV，每帧一行）；向本机 HN 服务发送版本化请求。
- `../../WCSNDM-0.0803-Windows-x64/hf_backend/hn_mel.py`：唯一 HN-SEP 推理、缓存、时间映射与谐波功率构造入口。
- `src/hn_harmonic.h`：复用已有 FLAG 数学与 LF 声门模型，计算逐帧相对增益；Mq 同时被普通路径调用。
- `hf_backend/logmel_v3_copy.py`：替换 `harm_power_spec`，复用现有非谐波处理与合并。
- `hf_backend/hf_daemon.py --hn`：本机 51766 端口，要求内部 HN2 协议并返回 OKHN2（用户 FLAG 仍为 HN1）。普通 HF 仍在 51765，旧服务不能冒充 HN 成功。
- 编辑器 `juce/src/backend/UtauRenderer.cpp::supportsComponentExport`：共用 FLAG 优先级，HN 禁止分离导出。

HN-SEP 模型沿用 HiFisampler v0.0.6 配套导出版本，来源、哈希及许可证在 `hf_backend/hnsep/`。需要 Python ONNX Runtime；本机配布使用已有 1.22.0 包的 CPU 推理提供器。

## 线性 FLAG 与分区适配专项核验（2026-10-15）

更新 172 安装版逐项核验 `g、Mo、QX/ME、Mr、Mq、Mt、Rd、NA`：八类均支持线性 FLAG；带类别标注的二段、三段、四段均支持分区 FLAG，并能与曲线同时使用。编辑器曲线菜单显示 `ME／共振峰强调`，与 `QX` 是同一参数。

优先级为 **该参数的线性曲线 > 本段固定 FLAG > 音符／轨道固定 FLAG**。空段继承固定值；曲线只覆盖自己的参数，其他参数仍按分区取值。曲线用输出时间轴，编辑器补偿前置发声；HN 谐波与 LLSM 噪声共用这一组已解析逐帧参数。二段、三段不会读取多余的第三／第四段数据；零长度中间段和短音也按存活边界处理。

普通 UTAU 的“固定辅音区＋拉伸区”支持上述曲线，但没有独立的分区 FLAG；这与谋•UTAU 中显式标注的二段是不同入口。界•UTAU 维持固定四区入口，谋•UTAU 可选择二／三／四段。HN1 是整音符内核开关，仍应放在音符或轨道固定 Flags 中，不在分区串或线性曲线中切换内核。

验证：`src/test-hn-regions.py` 直接调用日常配布引擎，共 **145 次真实模型合成、660 项检查**。按每一种时间映射生成固定值参照，逐帧比较八类曲线、全部参数同时变化、分区继承、优先级、别名和边界；覆盖源／输出时钟、零长度中间段及短音。报告：`test-output/update172/regions/verification.json`。

安装版编辑器另通过 `--smoke-flag-curve-mode`（不传引擎，仅验证开关／编辑数据／模式切换，不计为声音验证）与 `--smoke-mou-panel-counts`（二／三／四段切换、落盘、边界保留）。报告：`test-output/update172/regions-editor/verification.json`。此次未发现需要修改的功能代码，源码和配布可执行文件保持更新 172；本节为追加验证记录。
