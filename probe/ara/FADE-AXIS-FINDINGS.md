# F-1 实测：REAPER 的淡化轴映射

2026-10-09，REAPER **7.82/x64**，Windows x64。原始数据：`captures/fade-axis-7.82.json`
（6 个用例 / 50 个采样）。跑法：`../README.md`「无头跑探针：`run_probe_headless.ps1`」，
探针 `fade_axis_capture.lua`。

## 要回答的问题

官方头文件（`reaper_plugin_functions.h:2006-2015`）写明 7.81+ 由
`D_FADE*DIR_NEW`（curvature）与 `D_FADE*DIR2_NEW`（S parameter）决定形状，但**没有**
任何 fade 求值函数，也没有说明 `C_FADE*SHAPE` 的 7 个预设各自对应哪一组 `(curvature, S)`。
所以"新轴宿主上还能不能摆预设按钮"只能实测。

## 结论一：能。7 个预设各自对应一组确定的 `(c, S)`

只写 `C_FADEINSHAPE = k`（不碰任何新轴），读回 `D_FADEINDIR_NEW` / `D_FADEINDIR2_NEW`：

| 预设 `k` | 含义（`frontend/.../reaperFade.ts`） | `D_FADEINDIR_NEW` | `D_FADEINDIR2_NEW` |
|---|---|---|---|
| 0 | 线性 | 0 | 0 |
| 1 | 轻微凸（快起） | **0.5** | 0 |
| 2 | 轻微凹（快收） | **-0.5** | 0 |
| 3 | 陡峭凸（快起陡） | **1** | 0 |
| 4 | 陡峭凹（快收陡） | **-1** | 0 |
| 5 | 轻微 S（慢起慢收） | 0 | **0.5** |
| 6 | 锐利 S | 0 | **1** |

即：**预设 0/1/2/3/4 是纯 curvature 轴上的 5 个点，5/6 是纯 S 轴上的 2 个点**，
两轴正交，没有"必须同时给两个非零值"的预设。因此新轴能完整表达 7 个预设 ——
plan Task 1.3(a) 的"若新轴能完整表达 → 落成常量表"这一支成立，**不需要**降级成
"只给连续滑杆"。

一个可交叉验证的旁证：全新 item 的默认读数是 `SHAPE=1`、`DIR_NEW=0.5`、`S=0` ——
正好是预设 1 那一行。REAPER 的默认淡化形状就是"轻微凸"。

## 结论二：`C_FADEINSHAPE` 是**派生读数**，不是可写状态

- 写入 `k` 之后读回 `k`，同时新轴被推导成上表那一行 → 写预设**有效**，且是通过
  设定 `(c, S)` 生效的。
- 当 `(c, S)` 不是上表任何一行时，`C_FADEINSHAPE` 读回 **-1**（例如只写
  `D_FADEINDIR=0.5`，或写 `(c,S)=(-0.5, 0.5)`）。
- 写入顺序即权威顺序：先写预设 3（→ `(1, 0)`）再写 `D_FADEINDIR_NEW = 0.5`，
  结果 `(0.5, 0)` 读回 `SHAPE=1`；先写预设 5（→ `(0, 0.5)`）再写 `D_FADEINDIR_NEW = -0.5`，
  结果 `(-0.5, 0.5)` 读回 `SHAPE=5`。两次都说明**两个轴是分量，谁后写谁覆盖对应分量**。

推论：插件不该用 `C_FADEINSHAPE` 做往返（它只能表达 7 个预设 + -1），
应该把 `(c, S)` 当权威状态、把 `SHAPE` 当"恰好落在预设上时"的只读派生值。

## 结论三：旧 `D_FADEINDIR` 与新 `D_FADEINDIR_NEW` **不是同一套参数化**

写旧轴读新轴，与写新轴读旧轴，得到的都是**被重映射过的**值，不是原值：

| 写入 | 读回另一个轴 |
|---|---|
| 旧 `DIR = ±0.75` | 新 `DIR_NEW = ±0.6878` |
| 旧 `DIR = ±0.25` | 新 `DIR_NEW = ±0.1831` |
| 新 `DIR_NEW = ±0.75` | 旧 `DIR = ±0.7679` |
| 新 `DIR_NEW = ±0.25` | 旧 `DIR = ±0.5` |
| 新 `DIR_NEW = 0.5` | 旧 `DIR = 0` |

（`±0.5`、`0`、`±1` 是两套参数化的公共不动点；其余位置都不等。）

**所以绝不能把一个轴的值直接抄进另一个轴。** 插件若在旧轴宿主上读 `D_FADEINDIR`
再在新轴宿主上写 `D_FADEINDIR_NEW`，曲线会变 —— 这正是 plan Task 1.1 要求"按
`fade_axes_new` 分支"而不是"两个都写"的原因。

## 未解决 / 需要留意的

- **小数变体 1.1 / 5.1 不能照字面写进宿主**。`C_FADEINSHAPE` 在头文件里是 `int *`；把 1.1
  写进去实测读回 `SHAPE=0`（塌回线性）、`(0,0)`；写 5.1 读回 `SHAPE=7`（**超出文档的 0..6**）、
  `(0.5, 0)`。仓库 `state/model.rs:1387-1390` 把 shape 存成 `f64` 并声明"小数变体原样透传"
  —— 这在 HFS 自己的状态里成立，但**透传不到宿主的 `int *` 字段**：宿主侧看到的是被截断/
  改写的值。本次没有查清 REAPER 对 1.1/5.1 的真实内部编码，只记录"写进去读不回原值"。
- 本次只测了 fade-in 一侧。fade-out 四列在夹具里是控制组，读数与 fade-in 完全对称
  （`baseline` 里 `C_FADEOUTSHAPE=1`、`D_FADEOUTDIR_NEW=0.5`），故映射表同样适用于
  fade-out；`legacy_shape_then_new_dir` 之外的 fade-out 用例没有单独跑。
- `SHAPE` 的读回分类不止"等于预设"这一种：`new_s_only` 里 `(0.5, -1)` 读回 `5`、
  `(0.5, 1)` 读回 `6`，`new_dir_only` 里 `0.25` 与 `-0.25` 都读回 `2`。即 `SHAPE`
  是一个**多对一的粗分类**，不是精确匹配。反正结论二已经说明不该拿它做往返。
